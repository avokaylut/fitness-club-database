# Особенности работы базы

## Абонементы и посещения

Покупки хранятся в таблице «Клиенты_Абонементы». При покупке нового абонемента предыдущий действующий абонемент клиента переводится в статус «просрочен» или «закончился».

Первое посещение активирует абонемент. Отметки «посетил» и «опоздал» списывают одно занятие; неявка не активирует абонемент и не уменьшает остаток. При нулевом остатке устанавливается статус «закончился».

Срок действия сравнивается с текущей датой. Статусы обновляются при операциях с абонементом, а не по расписанию. Записи дампа отражают состояние базы на май 2026 года.

## Отзывы

Отзыв можно добавить, если у клиента есть запись о фактическом посещении выбранного занятия. Проверка не связывает отзыв с конкретной датой посещения и не контролирует порядок дат.

## Запросы

В `sql/03_queries.sql` приведены три примера:

- количество покупок по видам абонементов;
- посещаемость и заполняемость по занятиям и датам;
- расходы на ремонт оборудования.

Стоимость покупок рассчитывается по цене из каталога: отдельной цены сделки в базе нет. Запрос заполняемости показывает только даты, присутствующие в журнале посещений.

## Ограничения учебной модели

- Изменение или удаление посещения не возвращает списанное занятие.
- Контроль вместимости и защита списания при параллельных операциях не реализованы.
- Нет ограничений на список статусов, отметок посещений и отрицательный остаток.
- Абонемент «Безлимит» хранится как 99 занятий, без отдельной логики.
- Две из шести функций не подключены к триггерам.
- Данные дампа загружаются до создания триггеров и не проходят их проверки задним числом.

Для восстановления используется новая пустая база и файл `sql/01_restore.sql`. Исходный дамп в `source/` содержит команду `DROP DATABASE fit_club` и предназначен для хранения исходной версии.
