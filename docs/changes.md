# Подготовка проекта

Исходный дамп сохранён без изменений. Данные вымышленные; исходные имена и телефоны оставлены.

## Переносимый запуск

Из `sql/01_restore.sql` удалены команды удаления/создания базы, переключение подключения, назначения владельца `postgres` и служебные команды `restrict/unrestrict`. Схема, данные и определения функций сохранены. База создаётся отдельно, без требования локали `Russian_Russia.1251`.

## Исправления в `02_function_fixes.sql`

1. Имена таблиц и полей внутри функций явно заключены в двойные кавычки. В исходнике, например, таблица создана как `"Клиенты_Абонементы"`, но функция обращается к ней без кавычек. Это делает обработку регистра кириллических имён зависимой от окружения. В проверенной базе с локалью C исходная вставка прошла; кавычки добавлены для однозначности, а не как подтверждённая ошибка этого запуска.
2. Для функций задан `search_path = public, pg_temp`, чтобы обращения к таблицам не зависели от пути поиска в вызывающем подключении.
3. Неявка больше не активирует абонемент. Автоактивация выполняется только для отметок «посетил» и «опоздал».
4. В неподключённой функции обновления просроченных абонементов добавлено соединение с таблицей тарифов: поле срока действия находится именно там.

Состав таблиц и существующих триггеров не расширялся. Неподключённые функции сохранены, но автоматически не вызываются. Основные операции проверяются файлом `tests/smoke.sql`.

## Что осталось за рамками

- Нет ограничения допустимых отметок посещений, статусов и неотрицательного остатка занятий.
- Списание не защищено отдельной блокировкой выбранного абонемента от конкурентных операций.
- Срок сравнивается с текущей датой, а не с датой посещения. Загрузка задним числом требует отдельного решения.
- Проверка отзыва ищет любое фактическое посещение данного занятия; порядок дат посещения и отзыва не проверяется. В исходных данных есть отзыв клиента 12 раньше записанного посещения.
- Исходные данные загружаются до создания триггеров и не проходят их бизнес-проверки задним числом.
- Абонемент «Безлимит» представлен числом 99, отдельной логики безлимитного доступа нет.
- У покупки нет сохранённой цены сделки. Сумма по текущему каталогу не равна доказанной исторической выручке.
- Записи расписания не выделены в отдельные датированные сеансы, поэтому пример заполняемости показывает только даты из журнала посещений.

Это ограничения существующего учебного проекта. При оформлении они не заменялись вымышленными возможностями или результатами внедрения.
